# Architecture — Clotch

## What the project is
A macOS notch app that shows only the goals of Roberto's master Claude sessions and whether each goal is getting closer (issue #1). It started as a fork of CodeIsland (wxtsky, MIT, Swift): the notch shell, window and open/close motion come from it; the content is replaced by the goal list. App name `Clotch`, bundle id `com.squadd.clotch`, repo `SQUADD26/clotch` (issue #30; until then `Goal Notch`, `com.squadd.goalnotch`, repo `goal-notch`). Since issue #69 no CodeIsland or goal-notch name is left in the package, targets, sources, scripts or texts; only `LICENSE` (the MIT notice) and the README credit name CodeIsland. A normal app: Dock icon while it runs, app menu with Impostazioni… (Cmd+,) and Esci (Cmd+Q), a Dock click opens the settings. At the first launch `Sources/Clotch/main.swift` copies the old `com.squadd.goalnotch` UserDefaults once, without overwriting; then it renames the keys `goalnotch.rejectedProposals` / `goalnotch.seenMergedPRs` to `clotch.*` and deletes the old cache folder `Application Support/Goal Notch` (`ClotchCore/LegacyDefaults.swift`).

## Backend and where it runs
No backend. The app runs on Roberto's Mac only and reads local files, read-only. Its only write is its own cache, `~/Library/Application Support/Clotch/sessions-v<N>.json` (stat and parsed fields of each session file, so a restart re-parses only changed files; safe to delete). One exception, on Roberto's click (issue #20): «Accetta» / «Rifiuta» on a proposed goal run `python3 ~/.claude/hooks/obiettivo-guard.py conferma|rifiuta --sessione <cli>` (claude-config#1807) without `CLAUDE_CODE_SESSION_ID`, which write `~/.claude/obiettivi/` (`ClotchCore/GoalDecision.swift`); a rejected proposal leaves the notch only when the register drops it (no copy kept in the app, #171; a refusal the register did not take shows «Non rifiutato. Riprova.»). Second exception, the voice (issues #38, #50; `ClotchCore/VoiceFiles.swift`, `VoiceHooks.swift`, `VoiceTurn.swift`, `VoiceClean.swift`; app `VoiceSettingsPage.swift`, `VoiceSpeaker.swift`). The «Voce» page writes, on Roberto's save: the ElevenLabs key `~/.config/elevenlabs/api-key`, `~/.config/voce/config.json` (only `voice_id`, `model_id`, `speed`, `tetto_chiamate`, `tetto_caratteri`, and «Parla per» `parla_per` = `tutte` | `principali` (default: sessions with no parent session in the Claude app's session file) | `una` with `sessione` = a local id; other fields kept; a broken file is never overwritten), `~/.config/voce/spento` (voice off). Haiku's instructions and the pronunciation list are claude-config's own files, read and never copied or written (#84, claude-config#1837): the prompt `~/.claude/hooks/voce-parlatore.md` (the engine's, claude-config#1998; a Clotch from before #251 read it from the Clean View mod's folder: the mod no longer carries it, claude-config#2229, so the engine must be installed; missing or empty = the voice is silent), the base list `voce-pronuncia.json` (same folders, same rule) with Roberto's `~/.config/voce/pronuncia.json` on top (`{"parola": "come si dice"}`, whole words, an all-capitals key matches capitals only, applied to the text sent to ElevenLabs). Every file 600, folders 700, the key never read back. With the voice on and a key set, Clotch adds ONE Stop hook (command `~/.clotch/voce-stop.sh`, the script it writes) to `hooks` of every Claude Code folder's `settings.json` (`~/.claude` and each `~/.claude-*` with `settings.json` or `projects/`; minimal-diff edit like the inherited hook installer, a non-JSON file is never touched), once; voice off or no key removes the entries and the script. It writes the empty file `~/.config/voce/clotch` and touches it every hour while it runs (removed at quit and when the voice goes off): the hook queues the Stop payload in `~/.config/voce/coda/` only while that file is younger than 90 min, (Clean View's mod no longer speaks, claude-config#2229: Clotch is the only voice, and with Clotch closed nobody speaks; the file now only tells the hook to queue). The voice speaks only for news (#57, alerts engine `ClotchCore/VoiceEvents.swift`, `VoiceAlerts.swift`; app `VoiceAlertCenter.swift`): `richiesta_fatta`, `obiettivo_raggiunto`, `obiettivo_bloccato`, `fine_turno`, `domanda`, `rischio`, `avviso_custom`. If `~/.config/voce/eventi.jsonl` exists (claude-config#1854, contract `global/skills/overseer/eventi.md`, v 1, one JSON per line: `id`, `t`, `tipo`, `livello`, `sessione` {`cli`, `local_id`, `titolo`, `ruolo`}, `soggetto`, `testo`, `prova`, `giudizio`), only its events after launch count, found by the `t` and `id` of the last one seen, never by byte (read, never written). Otherwise Clotch derives them: a queued turn (older than 2 min: dropped) gives `domanda` from the questions of its last `giro_finito`/`needs_you` call, else an answer ending with «?»; the goals register going `raggiunto`/`bloccato`; a request going `fatta`; an account window crossing 80 % or 90 %; and the «Avvisami quando…» rules of `~/.config/voce/avvisi.json` (`{"v": 1, "regole": [{id "A-xxxx", creata, condizione, quando: {tipo: pr-fusa|sessione-ferma|file|ora|testo, valore, repo} | null, stato: attiva|scattata}]}`, written by the «Voce» page and by claude-config's `avvisami`; Clotch edits the file's own objects, so unknown fields stay, never overwrites a broken file, sets only `stato` = `scattata`, once, and checks them only without `eventi.jsonl`; a rule with no `quando` is the Overseer's). Before the engine, `richiesta_fatta`, `obiettivo_raggiunto`, `obiettivo_bloccato` and `fine_turno` without `giudizio` go to the Jev judge (`ClotchCore/VoiceJudge.swift`; the question is the config's file `~/.claude/hooks/voce_giudice_domanda.txt`, read and never copied, missing = the judge is not asked, #84; same three blocks as claude-config `voce_giudice.py`: Roberto's linked requests verbatim, the session's goal, the signal); no = silent, not reached (no question file, no key, error, over 5 s) = the fixed rules; every verdict appends a line to `~/.config/voce/giudice-log.jsonl` (600, never the key). The engine applies «Parla per» (`ruolo` master|overseer for «principali» and `local_id` for «una» when the event has them, else the session file; events with no session pass), one per subject in 10 min unless the new one is `alto` and the old one not, one of `richiesta_fatta`/`obiettivo_raggiunto` per session in 10 min, a queue of 3 (risks and questions first, `livello` alto ahead), no event older than 5 min. For each event said: checks `spento`, the key, `muto-<session_id>`, the daily caps in `giorno.json`; runs `claude -p --safe-mode --model claude-haiku-5-5` with the instructions (report on stdin, env `CLAUDE_CONFIG_DIR` = the account folder `ClaudeRun` picked (#159: the Dock-launched app has no CLAUDE_CONFIG_DIR and `~/.claude` may have no login; candidates = main folder, Settings extras, every `~/.claude-*`, ordered by the Macchine margin, first one `claude auth status --json` calls logged in, kept 10 min; stderr and exit status go to the log, category `ClaudeRun`, and a spoken question that fails shows why in the bar), `CLOTCH_VOCE_INTERNA=1` so the hook skips it; 22 s a try, two tries, then silence, #84: never the report itself, never a fixed sentence such as «guarda lo schermo», never «io dico/consiglio sì»); ElevenLabs TTS; writes `stato.json` (the light's contract below) and `ultima.json`; plays with AVAudioPlayer (speed above 1.2 by the player's rate). With the switch «Abbassa l'audio mentre parlo» on (`abbassa_audio`, default off, and `abbassa_livello` in percent, default 20, 0 to 80, both in `config.json`; #83) the other apps' audio goes down over 0.5 s before the first word, stays down 0.5 s after the last, and rises over 0.5 s (`ClotchCore/VoiceDuck.swift`: timing and the guarantee that it is always given back; app `AudioDucker.swift`). The tool is a Core Audio process tap (macOS 14.2+, `CATapDescription` of every other audio process, `mutedWhenTapped`) played back by a private aggregate device with a gain ramp. Clotch's own voice is not in the tap and the system volume is never touched, so the level returns exactly and a volume change by Roberto during the speech applies to both. The tap ends with the speech, at quit, or with the process. `Info.plist` has `NSAudioCaptureUsageDescription`: the first use asks macOS for System Audio Recording. Otherwise it writes nothing into `~/.claude`, `~/.codex` or other agent configs (the inherited hook installer, hook socket server, agent watchers and companion bridges are not started at launch). Third exception, the voice in (issue #110; Core `VoiceInput.swift`, `VoiceRoute.swift`; app `VoiceInputController.swift`, `VoiceCapture.swift`, `ScribeSession.swift`, `LocalTranscriber.swift`, `VoiceAsk.swift`, `OverseerDelivery.swift`, `VoiceInputPill.swift`, `DictationPage.swift`): the global shortcut `ShortcutAction.voiceInput` (default ⌥Spazio, UserDefaults; mode `tieni` = hold to speak and release to finish, a tap under 0.35 s leaves it open until the next press; mode `premi` = press to speak, press again to finish; the microphone is prepared at launch and after each utterance, keeps 0.4 s after the second press so the last word stays, a press while «sto pensando» starts a new utterance (#174); 300 s cap; log `subsystem == "com.squadd.clotch"`, category `VoiceInput`) records the microphone as 16 kHz mono (`NSMicrophoneUsageDescription`, entitlement `device.audio-input`) and shows the live text on a pill under the notch. Engine from `~/.config/voce/config.json` keys `ingresso_motore` (`scribe` default | `locale`), `ingresso_lingua` (`it` default | `en` | `auto`), `ingresso_a_voce` (default true), `ingresso_modo` (`tieni` default | `premi`), `ingresso_acceso` (default true; false = the shortcut does nothing), `ingresso_microfono` (unique id of the input device, "" = the system's), written by the «Dettatura» settings tab (microphone permission status with a button to Privacy, shortcut, mode, engine, language, microphone, spoken answers; the ElevenLabs key stays in «Voce»). `scribe` = ElevenLabs Scribe v2 Realtime WebSocket; `locale` = Parakeet TDT v3 through the FluidAudio package (Core ML model, ~480 MB downloaded once from Hugging Face, then no network). Where the text goes (`VoiceRoute.classify`, the registry rules of `richieste.py`): a question runs `claude -p --safe-mode --model claude-haiku-5-5` with read-only tools (Read, Glob, Grep, `gh` view/list) from `~/.claude`, at most 45 s, with the sessions Clotch sees on stdin (`<sessioni>`, one line each: title, state, minutes since the last activity; #174: reading the thousands of session files by hand took over 90 s) and the answer is said with the voice of the «Voce» page; an order is a file `~/.config/voce/ingresso/<ms>-<id>.json` (`{"v":1,"id","t","testo","da":"clotch-voce"}`, 600) that Clean View's mod in the Overseer's chat reads, submits as a prompt and deletes (deleted = received); the mod touches `~/.config/voce/ingresso/.ascolta` every 30 s while it listens. No fresh `.ascolta`, or the file still there after 20 s: Clotch deletes it, copies the text to the clipboard, opens the Overseer's chat (`local_id` in `~/.claude/overseer/attuale.json`) and the pill says to paste. With claude-config's helper file `~/.claude/hooks/helper_voce_prompt.md` present and not empty (claude-config#2116, read at every utterance, never copied), a question and an order (after its 2 s) go to the helper instead. The helper is the Overseer (clotch#286, claude-config#2241: one Overseer, this voice or a chat, same prompt, context and actions): `claude -p` from `~/.claude` with the model chosen in config.json `overseer_modello` (`VoiceInput.Config.overseerModel`, Haiku by default; budget 0.10/0.30/0.60 $ and 90/150/150 s for Haiku/Sonnet/Opus, `VoiceRoute.budget`/`helperSeconds`), those instructions as system prompt, Read/Glob/Grep and Bash only on `python3 hooks/helper_voce.py` (`stato` = the box, last actions, questions, sessions; `sessione <local_…> "<testo>"` = `dai-ok --forza` into that chat, the mail socket if dai-ok fails; `casella`, `ferme`, `sblocca`, `archivia`, `promuovi`, `apri`; `overseer "<testo>"` = the same inbox file); every action logged in `~/.config/voce/helper.log` as `[voce]`; its answer is shown and said. A helper that fails on an order: the inbox as below, so nothing is lost. An order waits 2 s on the pill («Annulla · 2», or Esc) before it leaves; Esc is a Carbon hotkey registered only while a dictation is open. Errors (microphone refused, key refused, credits over, no network, silence) are plain sentences with a button each (`VoiceInput.Failure`, no codes); the microphone error restarts by itself when macOS grants the permission. While he speaks the island's outline has a white light (red and flashing on an error), `VoiceInputLight.swift`.

Real time: one FSEvents stream with file-level events, batched by FSEvents to one callback a second. Each reload touches only the paths the events named (`GoalLoader`): the 1600+ session files are listed at launch and parsed only if changed since the on-disk index, then a rewrite costs one stat and one parse; only sessions in a shown goal's family reach the board, and an unchanged value publishes nothing. A full rescan happens only at launch, when FSEvents drops events, or when a new Claude app folder appears. A 30 s tick moves only the «since …» time; time-based state (yellow after 30 min still) is re-evaluated by a one-shot timer at the next instant it can change.

Tests in `PullRequestsTests.swift`.

- `sessioni/` (clotch#333 data layer, clotch#347 window base): a separate Electron + TypeScript app: its own code, but since #465 it ships inside `Clotch.app` (see Build), which `build.sh` builds through `npm run pacchetto:mac`. The main process reads, **read-only** (it never writes, moves or locks a file), the work sessions on the Mac and keeps them live. Sources, ported from the Swift parsers: Claude Code transcripts `<root>/projects/*/*.jsonl` for `~/.claude` and every `~/.claude-*` (roots folded by realpath, account = folder name, email from `.claude.json`, `ConfigPathIdentity`); Claude desktop session files (`claude-code-sessions/**/local_*.json`, same keys and filters as `GoalSources.parseSession`; they give title, `idApp`, archived/running; the folder `claude-code-sessions/<accountUuid>/` is the session's account, and its email is the `.claude.json` `oauthAccount` with that `accountUuid` (#996); a session run over ssh has no transcript on the Mac unless the app mirrored it as `projects/ssh-<id>/`, and the chat then says which host holds it); Codex `~/.codex/sessions/**/rollout-*.jsonl` (+ `$CODEX_HOME`); Cursor `~/.cursor/projects/*/agent-transcripts/<id>/<id>.jsonl` (subagent files are folded into the parent, as `CursorSessionFolding`); goals `~/.claude/obiettivi/<cli>.json` and true state `~/.claude/sessioni-stato/<cli>.json` joined by CLI id (same files as the table above). State: registry word if present (lavora / aspetta / ferma), else archived or goal reached = finita, else activity within 180 s = lavora, else ferma. The list reads only the first 64 KB and last 256 KB of each transcript (cache by mtime and size). Message history v1 (`src/cronologia.ts`, #443) uses one ledger shared by initial snapshots and live updates. Physical file identity, byte offset and revision distinguish messages, including identical text; tool updates preserve identity. Parsers warm from the head once. Pages of 50 belong to an immutable snapshot; authenticated cursors anchor that snapshot, so appends do not shift older pages. The renderer subscribes before requesting the initial snapshot, buffers live events through its watermark, and applies ordered deltas. Gaps, reset/truncate/rotation, missing metadata and expired cursors return explicit errors; retry starts a fresh snapshot when required, without content deduplication or polling repairs. Memory budgets are global per ledger: 96 MiB state, 128 MiB snapshots, at most 32 snapshots with five-minute TTL; inactive states/snapshots are evicted. Restore anchors are bounded to 4096 entries/8 MiB. A file above 128 MiB or a state exceeding its budget fails explicitly instead of silently truncating. Unchanged stat signatures avoid file reads; a changed file verifies the old prefix before append and detects rewrite/regrow. Live input uses existing fs.watch/debounce, with physical identities assigned where the event enters. API in `src/cronologia-tipi.ts`, `src/tipi.ts` and `src/preload.ts`: optional `{v:1,cursore?}` on `messaggi(id,pagina,opzioni)`, snapshot/watermark metadata in the response and deltas in `sessioni:aggiornamento`; legacy callers remain compatible. ### clotch AI: annullabilità locale (#452)
Il lettore Electron offre l'annullo soltanto per una decisione con inverso e ricevuta locale valida, come `friday_fiducia.locale` del motore. Legge `~/.claude/friday/eventi-locali/decisione/<id>` (o `FRIDAY_DIR`), senza scrivere: SHA256 dell'intero evento con serializzazione Python ordinata, Unicode UTF-8 e spazi standard. Eventi remoti, storici senza ricevuta o modificati restano visibili ma non annullabili. Il dominio delle decisioni prodotte oggi ha stringhe/argv, booleani/null e interi sicuri; numeri non interi o non rappresentabili sono rifiutati dal lettore. Il backend mantiene l'autorità finale sull'azione. Fixture generate dal produttore Python reale in `sessioni/test/genera-clotch-ai-ricevuta.py`; nessun processo Python aggiunto all'app.
